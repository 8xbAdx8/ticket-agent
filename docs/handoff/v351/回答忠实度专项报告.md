# V3.5.1 回答忠实度专项报告

日期：2026-10-26。范围：成员A新增确定性后置检查与离线专项，不是成员B正式评分，也不是修复后的Live成绩。本专项真实生成/Embedding请求均为0，原始V3.5回复、Trace、政策、30题与预算均未修改。

## 一、V3.5 原检查的实际不足

原`citation_check()`只核对引用ID是否属于实际检索结果，并将完整支持度/忠实度保留为indeterminate。这能识别P99之类未召回引用，却无法识别“引用P11但把15分钟写成30分钟”，也不能识别P01同一文档中48小时以上与24—48小时的费率错绑。原检查没有伪称已经证明全文正确；本轮是在其兼容接口之外增加可核对的细粒度证据。

## 二、新检查怎样工作

新增`target/rag_faithfulness.py`，入口为：

```python
from target.rag_faithfulness import check_answer

assessment = check_answer(
    reply,
    hits,                 # 实际search_policy工具结果，而非模型自己写的来源
    events=actual_events, # 实际tool_end事件，缺少时不能声称已经付款/下单
    question=user_input,
)
```

它不调用任何模型、Embedding或外部服务，也不接收Provider名称作为评分捷径。DeepSeek与Qwen面对同一回复/证据/事件时走完全相同的规则。原模型文字保存在`original_model_reply`，没有静默改写成成功答案。

检查分为：

- 引用真实性：逐句查`doc_id`是否出现在实际命中文档；显式用户引述和用于解释“该文档未涉及问题”的否定来源分开处理。未明确归属用户的Markdown引用仍需校验。
- 数量及范围：按引用定位政策子句，统一小时/分钟/天等单位，再核对期限、费率、金额、重量、次数等量。P01的“48小时以上”“24至48小时”“不足24小时”分支分别绑定，不能因为同篇文档出现过10%就认定10%适用。成人/儿童等明确主语也分别匹配。
- 引用支持：同一个数字出现在另一政策类别不等于支持当前结论；例如P11的15分钟不能支持“退票必须等待15分钟”。多个来源的数字无法在当前句正确绑定时标记待人工复核。
- 额外事实：检测无来源数值、部分明确新增限制（如强制购买保险）、有限已知禁令被反转的表达，不把未认识的自然语言约束硬判为正确。
- 无证据：明确拒答和无证据仍声称金额/期限分开判定；“无法确认，但是可以理赔100元”不能靠一句拒答蒙混通过。
- 冲突：实际证据同时给出不同锁座期限时，回答选择其中之一却不披露冲突会失败；无法自动证明的其他冲突仍需人工。
- 执行事实：声称已锁座/下单/支付/取消，或已调用某工具，必须有对应`tool_end`、`ok=True`且`executed=True`。失败事件、未实际执行、没有事件均不能支持成功声称。假设、否定和用户原话不会直接等于已经执行。

## 三、判定与不确定项

`status`只使用以下三类：

| 状态 | 含义 |
|---|---|
| failed | 有可指出的错引、数值/条件/类别矛盾、无证据正向事实或虚构操作 |
| checked_scoped_facts | 有有限、可核对的局部事实；不能推断整篇回答正确 |
| indeterminate | 引用范围、隐含条件、模态或语义不足以自动判定，需人工复核 |

每项返回`claim_checks`、`findings`、`manual_review`与具体引用子句。**所有结果的`full_semantic_faithfulness`仍为`indeterminate`**，不能把有限规则通过写成“回答忠实度100%”。“也许”“条件未说明”“多文档复杂绑定”等保留人工，不把不确定语义伪造成确定分数。

## 四、实际离线结果

固定专项原件：`cases/rag_faithfulness_v351.json`，55个fixture，每项均保存输入、权威工具结果、模型文字、执行事件和预先确定的断言。没有改动原30题或B正式用例。

实际运行：

```powershell
.\.venv-v35\Scripts\python.exe -m unittest discover -s tests -p test_v351_faithfulness.py -v
```

55个逐例断言及3个范围测试：**58通过、0失败、0跳过**。逐例实测判定为27个明确失败、14个有限事实已核对、14个待人工；这55个断言均与预期相符。故障fixture的“被判失败”是预期检出，不是55个正常模型回答都通过，更不是Live准确率。

重点反例：F05同文档费率错绑、F25额外保险限制、F28/F30成人儿童额度互换、F34/F55引用存在却不支持结论、F43/F44显式否定数字、F49否定来源后夹带金额、F53/F54块引用归属。F36/F37使用保存的真实Qwen回答原文进行离线复核，不重新生成，不覆盖历史初评。

逐项输入/证据/原输出/断言/实际判定和源码、fixture SHA256见`docs/evidence/v351/faithfulness/fixture_results.json`，实际单测输出见同目录`unit-test.txt`。生成策略、完整Agent集成、最终全量回归与Git SHA由主交接报告汇总；本报告不借局部测试宣称整项目已验收。

## 五、B应独立复核的风险

规则目前围绕现有15条模拟政策和显式表达，不能覆盖所有同义、跨句指代、数字文字混写、复杂冲突或提示攻击。新政策与未知语义可能需要人工复核；有限条件解析仍可能误报/漏报，建议B增加未见表达并核对具体`findings`，不要通过放宽正式断言换取通过。

没有API重测，因此不能称作修复后真实模型已经全部准确。后续需要明确授权后，分别评价“模型原回答质量”和“后置保护是否正确拦截”，保留二者独立结论。
