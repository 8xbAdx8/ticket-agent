# C：V3.3 多模型与观测演示说明

日期：2026-10-25。本轮新增百炼调用代码和可选 LangSmith 上传，不再只是占位页面。但当前交付只验证过离线桩，没有新的真实 DeepSeek/百炼/LangSmith 成功记录。

## 可以怎么介绍

“同一个票务助手可以选择两个真实模型。模型负责理解和选择工具；LangChain 帮它执行循环；原 Python 工具查询虚构数据。无论使用哪个模型，都只能查模拟余票和政策，不能办理真实购票或支付。LangSmith 可在用户确认后接收经过过滤的本轮记录，本地证据仍独立保存。”

Mock 是可控制的离线规则，适合可复现测试；真实模型存在变化，不能把两种成绩混为一谈。LangSmith 是观测服务，不是另一种聊天模型。

## 启动与配置

已有环境时双击原 `启动_离线模式.cmd` 演示 Mock。真实模型用 B 手册的安全环境变量和新命令：

```powershell
cd D:\codexproject\ticket-agent
# 仅检查配置，不发模型请求
.\.venv-deepseek\Scripts\python.exe scripts/live_providers.py --provider bailian
# 配置完整后启动网页；打开网页本身不调用模型
.\.venv-deepseek\Scripts\python.exe scripts/live_providers.py --provider bailian --serve --port 8503
```

Key 用本地隐藏输入设置，不交给队友、不出现在录像中。百炼地址/模型须与自己的账号匹配，示例不保证账户权限。拉取更新后重新启动服务。

## 获授权后怎样录真实流程

先由 B/用户按手册明确运行真实命令并核查证据，再录制同一结果。初次两个 Provider 合计最多三次生成，通常一次查票闭环两次；不为拍摄反复重跑、不要删账本。若预算不足应停止。

推荐片段：用户查票 → 模型真实 tool_calls → Python 模拟结果 → 模型最终回答 → Trace 里的 Provider/实际模型/用量/时间/SHA。政策同样需要 search_policy 来源；没有执行的场景写待验证。

如演示 LangSmith，先检查实际预览、确认上传，再展示本地 Trace ID 和独立 remote_run_id、POST/GET 核验回执。只有 `verification_origin=remote_http` 且 `remote_verified=true` 才能说远端已核验；桩回执/配置存在/仅 POST 被接受均不够。上传失败不表示查票一定失败，业务与观测分别讲。

## 5 分钟初步顺序

- 0:00–0:45：三人分工、模拟业务范围、两个模型与观测服务各自职责。
- 0:45–1:45：四模型选择、Key 不入界面、缺配置禁止发送、预算提示。
- 1:45–3:15：已获得真实证据时展示查票闭环；否则明确只演示离线工具及新入口，不能称真实 API 通过。
- 3:15–4:15：原 Trace 与新增元数据；解释未知 Token、业务成功和模型成功的区别。
- 4:15–5:00：可选 LangSmith 的范围/脱敏/独立回执，最后说明未完成的在线验收。

## 报告边界

A 完整依赖环境 256 项离线自测通过，不是 B 的正式成绩，也不是 256 次真实对话。本轮真实生成 0、远端上传 0，新增费用 0 的依据是没有请求。历史 DeepSeek 证据须标旧日期/版本；百炼与 LangSmith 本轮待验证，不能借用历史结果。

最终比较成绩、政策忠实度和缺陷评估由 B 提供。C 需要在自己的机器验收安装/启动/显示与录像，再形成最终作品报告。现阶段为有条件交接。
