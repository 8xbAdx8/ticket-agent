## 这次升级能讲什么

Ticket Agent 用自建模拟数据处理查票、政策和模拟订单。V3.2 的主要升级是让测试过程能追溯：用户问了什么、模型要求调用什么工具、参数如何变化、后端有没有真正执行、结果是否可信、哪条规则发现问题，都能找到对应记录。

“开了缺陷开关”不等于“真的注入了缺陷”；“成功注入”不等于“Agent 发现并修好了”。新面板把它们拆开。红色的业务质量失败可以恰好证明测试平台成功发现受控缺陷，不应剪辑成“全绿成绩”。

本轮所有新增演示证据是离线 Mock、SDK 桩或模拟后端并发，不是新 DeepSeek 实测。V3.1 有独立历史真实 API 证据，保留原日期和目录；不要用历史结果证明 V3.2 新能力已在线验证。

在 PowerShell 中执行，保持终端窗口运行。若已有 8501 服务，请先辨认来源，不要直接关闭别人的进程；可将最后一行加 `--server.port 8502` 后访问对应端口。

## 推荐验收和拍摄顺序

| 顺序 | 操作与输入 | 应检查的真实现象 | 适合截图 |
|---|---|---|---|
| 1 正常基线 | 恢复正常模式、清会话，输入“查今天上海到杭州高铁二等座” | 有实际 query_tickets，右侧参数、结果、唯一 Trace ID；没有 G9999 | 正常查票卡片与调用事实 |
| 2 M7 | 勾 hallucinated_train，新会话同样查票 | 权威库及 original_result 无 G9999；可见 result 多出 G9999；检测命中文本片段 | 原始/变异前后与独立判定 |
| 3 恢复 | 恢复正常模式后重新查票 | 不再注入假车次，不能沿用旧污染会话 | 正常/变异/恢复三组对照 |
| 4 M8 | 点击“运行并发订单对照（离线）” | 正常同锁座 1 单，受控影子库 2 单；唯一性断言失败，平台检出为是，临时资源已清理 | 请求对应订单号及落库数量 |
| 5 政策 | 正常模式问“锁座后多久必须完成支付？” | search_policy 原政策编号和公开回复，可检查来源 | RAG 来源和工具结果 |
| 6 回放 | 历史记录回放选记录及诊断 ID | 只读取当时文件；没有新模型运行；旧记录缺元信息时直说缺失 | trace_id、断言名、证据引用 |

M8 开关在普通聊天中会提示不适用；它需要独立并发按钮，不用对话随机碰撞。其变异是测试专用影子库和屏障调度，不是发现正常数据库本来有重复订单。

同一个锁座的多个请求可以同时到达，正常后端用事务及唯一约束维持一单。不同锁座也有独立场景，不受应用层全局互斥串行化；SQLite 自身仍顺序提交写事务。拍摄时用“请求并发到达、数据库保持一致”描述，不说“多个线程同时写入磁盘”。

## 如何讲清面板

逐项解释：

1. 注入成功：注入层真的改了参数/结果/调度吗？
2. 平台检出：独立规则是否发现错误日期、假车次或重复订单？
3. Agent 识别：是否有可检查的行为证据？未知就保留待判定。
4. Agent 恢复：实际修正操作和最终业务都正确吗？仅一句自称不算。
5. 安全停止：是否由明确上限或后端校验止住错误？停止不表示买票成功。
6. 业务结果：条件、来源与状态是否正确？不要只看工具返回成功。

M7 是人为注入工具结果，不能讲成“DeepSeek 自发编造了 G9999”。SDK 桩文件的 provider 可沿用 deepseek_live 协议名称，但新增 evidence_kind=offline_sdk_stub 明确其来源，必须按“离线协议桩”介绍，不能按真实模型成绩介绍。

## 已保存证据怎么用

`docs/evidence/v32/20261018-negation-fix/report.json` 是总索引；cases/ 保存逐例诊断文件及必要大对象。25 条 Agent/后端对照记录、8 条规则样本已实际生成。6 条可判定的幻觉规则样本均符合预期，2 条含糊样本排除；不能把这个数字写成通用模型准确率。

Web 可回放指定目录中的旁证。若只想看交付证据，不要 seed，不要点发送：停止当前演示终端，重新设置 `$env:AGENT_TRACE_DIR="$PWD\docs\evidence\v32\20261018-negation-fix\cases\sdk-date_offset"` 后启动 Web，进入历史诊断列表。该目录可能没有原十字段 traces.jsonl，主列表显示暂无记录是正常的，独立诊断列表仍可读。**不要在交付证据目录发送消息或运行并发按钮**；互动演示始终使用上面新建的 artifacts/runtime 目录。

验收失败时保留终端输出、完整 Trace、对应 audit_runs.jsonl 和 audit_blobs、Trace ID、操作步骤与截图，不重跑替换失败记录。截图避开认证信息、真实个人信息与私人文件路径。脱敏侧证不含内部思维链，加载动画只是“正在处理”，不能解释为模型的隐藏思考。
