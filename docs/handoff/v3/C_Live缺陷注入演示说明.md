# Ticket Agent V3.1 Live 缺陷注入演示说明

2026-10-18，供成员C验收、截图与讲解。当前六种变异已有真实DeepSeek触发证据，但正式质量分数仍由B提供。

## 怎么解释这个功能

DeepSeek负责理解需求并选择工具，LangChain负责把模型与Python工具串起来，工具查询的是自建虚构票务库。故障注入层故意在这条链路中制造可控错误，让测试员观察Agent有没有发现、有没有正确处理。它不公开模型内部思维，也不对接真实12306、航司或支付。

“注入成功”表示确实制造了指定变化；“Agent发现错误”表示模型或保护层识别了问题；“任务恢复成功”表示最终重新完成正确任务。这三者不同，不能把开关打勾或HTTP200直接称作通过。

## 先选现场演示还是历史回放

- 历史真实证据：`docs/evidence/deepseek/v31-live-faults-20261018/`，27次真实生成请求、输入42038/输出3733 Token，实际费用未知。打开summary.json及具体case.json/Trace即可核对，不消耗新额度。
- 现场Live：由团队配置Key和费用预算后启动DeepSeek。发送消息才产生费用；模型可能追问或没有触发工具，要按实际表现讲解。
- Mock：适合不联网排练，页面必须保留Mock标记；不能把Mock动画、离线SDK桩或AppTest结果剪成现场真实模型证据。

首次演示优先只读模式，网页会显示DeepSeek Live · 只读。六开关可见，旁边显示注入阶段；写变异在此模式会标为不适用，不自动扩大权限。

## 推荐演示顺序

| 顺序 | 操作 | 应拍摄的画面及判定 |
|---|---|---|
| 1 | 关闭变异，查明天上海到杭州二等座 | 模型来源、回复、query_tickets参数和实际班次；正常结果来自工具 |
| 2 | 开date_offset，再查同一路线 | 原日期2026-10-19→执行2026-10-20的历史证据；当日现场日期应按实际变化。历史模型指出日期不一致，不能说它自动重查成功 |
| 3 | 开route_error，问锁座支付时限 | 模型请求search_policy，实际执行query_tickets；历史模型说明拿到的是余票、无法回答政策 |
| 4 | 恢复后开no_citation，问支付政策 | 原hits含编号，变异后移除；模型明确说明doc_id缺失。不是在最终文字上删几个字符 |
| 5 | 恢复后开repeat_call，查票 | 一个模型请求对应两次Python执行，展示execution_index和实际工具表，不说“模型调用了两次” |
| 6 | 展示全工具模拟沙箱的历史正常/skip_lock对照 | 正常1锁/1待支付订单；故障真实下单被后端拒绝、0锁/0订单。强调没有真实付款 |
| 7 | 展示infinite_loop_selected历史证据 | 模型请求监控1次、Python实际3次，然后max_steps_exceeded；不是无上限地花API费用 |

切换开关会清空当前内存会话以免污染，旧记录仍在历史文件。页面“实际缺陷注入证据”显示applied/blocked/未触发/不适用；展开可看完整前后参数和结果。预算耗尽或异常必须保留错误画面，不自动换成Mock假装成功。

## 两个适合讲清楚的真实对照

首轮购买与监控时，模型没有直接执行，而是询问要选哪个车次。因此注入层记录未触发。之后A用明确班次和明确授权的新场景取得注入证据，原样保留前两次结果。这能说明我们没有把模型随机行为硬改成预期输出。

skip_lock后，模型两次提出锁座请求，但注入层把它们改为无效lock_id的下单；原业务后端均拒绝。应用最终报告tool_execution_failed，原模型文字仍在model_final事件中。演示时应说“故障被后端约束挡住”，不能说“绕过锁座成功买票”。

## 5至10分钟视频建议

0～1分钟介绍分工、真实模型与模拟业务；1～2分钟正常查票和轨迹；2～4分钟日期/路由/引用三个只读故障；4～5分钟重复执行次数；5～7分钟沙箱跳锁座和有限循环；7～8分钟展示两次未触发样本、费用与局限，并说明最终成绩由B提供。时间更短时，沙箱部分用明确标注的真实历史回放。

截图建议保留模式标记、当前变异、执行表、变异前后JSON、终止原因；报告中说明日期和是否历史回放。不拍Key、环境变量值、认证请求头或任何模型原始内部推理内容。

## 不能宣称的事项

不能宣称真实八工具全部通过、真实支付成功、B已给出V3.1正式Live通过率、模型完全不会幻觉、一次提示异常就代表恢复成功。当前仅验证有限样本，真实费用未知，思考模式、并发压力和多次稳定性尚未验收。
