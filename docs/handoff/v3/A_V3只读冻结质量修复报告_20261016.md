## 错误、契约与证据

正常返回与最大步数结束仍是 docs/contract.md 的 10 顶层字段、5 call 字段，finish_reason 仍仅 stop/max_steps_exceeded。stop 不表示业务成功。docs/contract.md、Trace 类、原 8 工具、MockProvider、业务数据库实现和依赖锁均未改。

| 情况 | 现在实际行为 |
|---|---|
| 400/401/402/422/429/500/503 | 脱敏 DeepSeekError 分类，0 自动重试；失败旁证，无伪成功正常 Trace |
| 超时/网络失败 | timeout/network_connection；预算占位不退款，因为是否执行未知；不自动重试 |
| 预算耗尽 | request_budget_exhausted；在传输前拒绝，原账本不增加 |
| Token 元数据缺失 | token_usage_unknown；完整 tokens=null，只保留已确认的 observed_tokens |
| 工具抛异常/返回 error/后端 ok=false/错误写调用 | 真正记录 ok=false 与结果；若框架最终结束，整轮 tool_execution_failed，不接受模型的成功结论 |
| 模型仍邀请锁座/下单/支付或声称完成 | read_only_capability_violation；原始最终文字留 model_final，无成功替换 |
| 畸形工具调用 | invalid_tool_call；保留坏调用事件，不执行后端 |
| 最大模型步数 | 原契约 max_steps_exceeded，保留实际调用和已确认用量 |

**异常接口边界须由 B 显式处理：** 原契约没有错误字段、nullable Token 或 error finish_reason，本次不擅自扩展它。API/未知 Token 继续沿用既有 DeepSeekError；工具失败和能力拒绝现在也使用这一错误通道。不是保证所有 chat 都返回字典。失败没有普通 traces.jsonl 行，保存于独立 deepseek_runs.jsonl；这是既有异常通道的加固，不能说“每次失败也有完整普通 Trace”。B 执行器若仅索引返回 dict，必须在适配层捕获异常并计为错误/阻塞，不能调整正式断言换分。

错误旁证含 error、tokens=null、tool_attempts（原 calls 结构）、tool_sequence、observed_tokens（已确认部分，不能当整轮总用量）、events 的 model_final/invalid_tool_calls。正常公共 JSON 没有新增这些字段。CLI 错误退出码 2、诊断对象 tokens=null；Web 展示类别和旁证位置。错误后当前内存会话清理，磁盘历史不删，重新查询需给完整条件；其他会话不受影响。
