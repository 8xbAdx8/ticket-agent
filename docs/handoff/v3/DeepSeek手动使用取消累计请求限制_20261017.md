# DeepSeek 手动使用：取消累计请求次数限制

日期：2026-10-17。依据：用户明确要求“把这个限制取消掉”。状态：【已实现并离线验证】；本次没有发送真实 API 请求。

## 改动与原理

- `target/deepseek_runtime.py`：环境变量 `DEEPSEEK_MAX_REQUESTS=0` 表示不限制累计请求数。每次请求仍经过原传输检查、SQLite 请求记账和响应状态/Token 记录。`snapshot.limit=0` 表示无限制，不表示没有剩余额度。
- 默认值仍为 5；1～5 的配置仍按原有规则拦截超额请求，负数及大于 5 的配置仍拒绝。恢复受限配置时，已记录的请求继续计入累计次数。
- 只读工具仍仅 `query_tickets`、`search_policy`；其余六工具仍由代码禁止。单轮模型/工具调用上限、输出 Token 上限、单轮 Token 预算、超时、零自动重试、脱敏和 Agent.chat 返回契约不变。
- `tests/test_deepseek_runtime.py`：新增 3 项离线测试，覆盖跨客户端第 6、7 次请求可执行且持续记账、重新启用上限后拒绝超额请求、取消总次数上限后仍拒绝六个非白名单工具，以及默认值和负数检查。全部使用 MockTransport，不是真实模型表现。
- 本机忽略目录中的 `artifacts/runtime/manual-deepseek-20261017-user5/start.ps1` 和 `prepare.py` 已同步改为无限累计次数，保留同一数据库、Trace 目录和账本。目录名保留历史名称，不代表仍有五次限制。这两个文件是本机运行辅助文件，不随 Git 克隆交付。
- README 与持续开发记录补充当前使用状态，历史运行证据保持原样。

## 本机启动

已有网页若在运行，先在其终端按 Ctrl+C，然后执行：

```powershell
& "D:\codexproject\ticket-agent\artifacts\runtime\manual-deepseek-20261017-user5\start.ps1"
```

打开终端打印的 `Open: http://127.0.0.1:端口`。脚本读取已配置的 `DEEPSEEK_API_KEY`，不会显示或保存 Key。网页应显示 `DeepSeek Live · 只读`。在输入框发送“查明天上海到杭州的高铁二等座，请列出有余票的车次”。仅点击发送才请求模型，业务仍为虚构票务数据。

其他现有启动流程只需在启动前显式设置：

```powershell
$env:DEEPSEEK_MAX_REQUESTS="0"
```

其余 DeepSeek Provider、LangChain 引擎、只读工具集、模型与独立数据库/Trace/账本配置保持原设置。进程启动后读取配置，修改变量需要重启。不要删除或重置账本；取消累计上限仍会正常产生供应商 API 费用，不代表免费，也不取消供应商余额和速率限制。
