# 对话滚动架构与当前运行常驻显示（2026-10-30）

> 目标：长对话中不必滚动整页就能看到运行状态与输入框。本轮只做布局与滚动架构，不改业务。

## 1. 修改文件与设计选择

| 文件 | 改动 |
|---|---|
| `web/scroll_bridge.py`（新增） | 同源 iframe 里的少量 JS：只操作对话容器，负责高度适配、位置记忆、新消息提示、跳转执行 |
| `web/run_view.py` | 新增 `run_summary()` / `run_summary_line()`：把「当前展示的那次运行」压成一行摘要，纯函数、可测 |
| `web/conversation.py` | 页面重构：置顶运行摘要条 → 对话滚动区 → 输入区；确认卡与输入区抽成 `_confirm_cards` / `_composer`，放进对话列 |
| `web/design.css` | 滚动容器、粘性摘要条、状态标签、新消息胶囊、窄屏规则 |
| `tests/test_scroll_layout.py`（新增） | 12 条：token 契约、摘要绑定、跳转按钮、run_id 隔离 |

### 结构

```
header（标题 + 定位）
运行摘要条（position: sticky，含 run_id / 模式 / 状态 / 阶段 / 最近工具 + 两个跳转）
┌ 对话列 ────────────────────────┐ ┌ 运行详情 ┐
│ st.container(height=...,        │ │ 折叠的     │
│   key='user_chat_scroll')       │ │ 「运行详情 │
│   → 独立滚动                    │ │  与 Trace」│
│ 确认卡（如有）                   │ │            │
│ 输入区（固定在这列底部）          │ │            │
└─────────────────────────────────┘ └────────────┘
更多模拟工具（折叠，页面下部）
```

关键选择：**输入区放进对话列内部**。放在列外时，窄屏栈式排列会把右栏夹在对话与输入区之间，输入框被推到屏幕外（实测 `composerBottom=1280 > 820`）。放进列内后顺序恒为「对话 → 确认 → 输入 → 详情」。

## 2. 旧机制与新机制

| | 旧 | 新 |
|---|---|---|
| 页面滚动 | 整页随内容增长，输入框和运行栏被推走 | 页面高度锁定视口（实测 `pageScrollHeight == innerHeight`），只有对话区滚动 |
| 对话滚动 | 无容器，靠整页 | `st.container(height=...)` 原生滚动容器 |
| 高度 | 固定值 | JS 按「视口 − 顶部偏移 − 输入区高度」实测；CSS `clamp()` 兜底 |
| 位置保持 | 无，rerun 后靠浏览器 | `sessionStorage` 记录 `top / atBottom / turns`，rerun 后恢复 |
| 新消息 | 无提示 | 阅读历史时插入「有新消息 · 回到最新」胶囊，不强行拉到底 |
| 定位 | 无 | 「回到最新」滚到底；「回到本次运行」滚到当前 run 的最后一轮并高亮 |
| 全页滚动 | `window.scrollTo` 一类 | **不使用**；`tests/test_scroll_layout.py` 断言桥接 HTML 里没有 `window.scrollTo` |

高度落点的坑（已解决，写在代码注释里）：Streamlit 把固定高度放在 `stLayoutWrapper` 上，且它是 `flex: 0 0 <height>px` 的弹性项——只改 `height` 无效，必须同时改 `flex-basis`；`min-height` 也要一起改，否则缩小视图时不生效。

## 3. 实测结果（Chromium headless，CDP 读取真实布局）

### 一屏放下 + 输入框常驻

| 视口 | 对话容器高 | 输入区底部 | 页面高 | 结论 |
|---|---|---|---|---|
| 1440×900 | 500 px | 876 | 900 | 一屏内 |
| 1440×720 | 320 px | 696 | 720 | 一屏内 |
| 900×820 | 362 px | 796 | 820 | 一屏内、无横向溢出（`scrollWidth=900`） |

### 滚动行为（1440×900，5 轮真实对话，内容高 1636 px）

| 步骤 | scrollTop | 结果 |
|---|---|---|
| 连续发送 5 条 | 1636 = max | 发送后跟随到底部 |
| 手动上滚 | 120 | 停在阅读位置 |
| 切换主题触发 rerun | 120 | **位置保持**，未回顶也未回底 |
| 点「回到最新」 | 1636 | 回到底部 |
| 点「回到本次运行」 | 1535 | 跳到当前 run 的最后一轮（非底部），并高亮 |

### 新消息提示（3 轮对话 + 确认一条模拟下单）

| 步骤 | scrollTop | badge |
|---|---|---|
| 上滚到顶部阅读 | 0（`atBottom=false` 已持久化） | 无 |
| 在阅读状态下确认操作，产生新回合 | **0（没有被拉走）** | **出现「有新消息 · 回到最新」** |
| 点击胶囊 | 465 = max | 回到底部，胶囊消失 |

### 关于「自动跟随」

发送消息是**用户主动行为**，因此发送后显式滚到新消息（符合要求 1）；阅读历史期间由确认操作带来的新内容不抢滚动条，只给提示（符合要求 3、5）。

## 5. 仍存在的限制

1. **桥接依赖同源 iframe**。Streamlit 的组件 iframe 带 `allow-same-origin`，脚本才能访问父页面；若未来 Streamlit 收紧该属性，高度适配与位置保持会退回「CSS 兜底 + 不保持位置」。
2. **执行极快时看不到中间帧**。离线 Mock 单轮约 5 ms，`执行中` 阶段条依然截不到（沿用上一轮结论）。
3. **`sessionStorage` 按标签页隔离**：新标签页从底部开始，不继承另一个标签的阅读位置。
4. **窄屏按钮文字被省略**（「回到本次…」）。功能正常，但 900 px 下按钮可用宽度约 95 px。
5. 并行任务（Codex）本轮也在改 `web/conversation.py`、`design.css` 等文件；我在合并处发现过重复的 `user_compose` / `action_confirm` 键并已消除，但**并发编辑期间仍有冲突可能**。
