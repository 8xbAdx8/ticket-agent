## 2. 环境阻塞与修复（必须先说明）

本轮开工时遇到两级 Windows 文件权限问题，均由 DSH 沙箱授权未正确传播导致：

1. `SetNamedSecurityInfoW failed (Win32 5): grantWrite(D:\codexproject\ticket-agent)` — 工作区根目录缺少写权限。用随附的 `diagnose-windows-sandbox-acl.ps1` 修复并验证（`WRITE_OWNER` false → true）。
2. 根目录修好后**只有根可写**：文件能改，但任何已存在子目录内**无法新建目录**（`web/`、`artifacts/runtime/` 等全部失败），而应用每个会话都要建 `artifacts/runtime/v33/user/<sid>/`，测试也要建运行目录 → 应用根本起不来。根因是第 1 步授予的权限项没有继承标志。补一条可继承的「本人账号完全控制」后恢复。

- 被拒绝的路径、诊断记录与还原脚本：`D:\codexproject\dsh-acl-recovery\`
- 还原方式：`pwsh -NoProfile -File 'D:\codexproject\dsh-acl-recovery\acl-backup-4b16459bad3c43f2bdf32551db9d663d.json.ps1' -Path 'D:\codexproject\ticket-agent' -AllowRoot 'D:\codexproject\ticket-agent' -Restore '...json'`，再移除后加的可继承项。
- 该问题属于 DSH 沙箱在工作区已存在且 ACL 曾被第三方沙箱改写时的场景，未在本轮代码里绕过。

## 5. P1 开发者端（追加）

针对交接书列出的四条问题：

| 交接书问题 | 处理 |
|---|---|
| 三栏关联不够直观 | 顶部「运行选择」条说明规则；两个选择器直接把会话与运行列出来（`01 · <run_id> · 当前运行`）；三栏顶部各有一条运行身份条（模式标签 + run_id + 会话 + 事件文件是否可读），三处指向同一个 `run_id` |
| 中间时间线可能无记录，右侧独立调试却能运行，易误以为是同一次运行 | 独立调试成为**自己的会话和自己的一次运行**；执行完自动聚焦到它并标「独立调试」；中间栏只渲染 `run_id` 相同的事件；运行没有事件文件时回退审计旁证，并显式写「不是同一次运行的事件流」 |
| 提示词 / 工具 Schema / 权限 / Trace / 政策证据 / 测试结果缺乏关联 | 左栏：提示词来源与 SHA-256、工具 Schema、权限矩阵、规则→用例映射（均标来源）；中栏：输入、模型请求/返回、工具提议、参数校验、开始执行、工具结果、RAG 检索、最终回复、异常；右栏：输入与结束原因、实际工具参数与结果、政策证据、自动断言与变异、完整审计旁证 |
| 静态说明、当前真实事件、历史回放需严格区分 | 三种模式：**当前运行**（最新会话的最后一次运行）、**历史回放**（其余已保存运行）、**独立调试**（调试会话）。三栏只按选中的 `run_id` 取数 |

改动文件：`web/developer_workspace.py`（重写）、`web/design.css`（运行条、运行身份条、模式标签、配置页签收窄）、`tests/test_developer_runs.py`（新增 5 条：模式分类、结果绑定、身份条转义与事件文件状态）。

保留的既有契约：`证据会话` / `运行记录` / `纵向布局（窄屏）` 控件，`selected_event_<run_id>_<i>` 按钮键，左侧 `工具配置` 页签，`developer_debug_form` / `调试消息` / `执行离线调试`。
