## 一、可如实介绍的亮点

原系统用关键词找政策。V3.5把15条模拟政策送到真正的text-embedding-v4，生成1024维向量，存入本地Chroma；问题也真正向量化，再找相近政策。Qwen3.8-Flash依据证据回答，且曾自主选择查票工具并接收Python结果。票价/库存仍来自模拟SQLite，没有真实售票/支付。

生成模型负责理解、选工具与回答；Embedding负责将文字变成向量；Chroma负责持久保存和检索；原Python工具负责票务状态。系统记录三者实际过程，不显示内部思维链。DeepSeek保留，但本轮没有同证据的新DeepSeek生成对照。
