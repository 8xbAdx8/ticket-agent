# 成员C：验收与演示交接

## 项目怎么介绍

Ticket Agent让用户用自然语言查询虚构高铁/航班、咨询模拟政策，并在离线Mock模式演示订票流程。普通聊天机器人只生成文字；本项目会调用Python工具，依据模拟数据库或政策检索结果回答，并记录工具参数、结果、耗时和引用，便于测试团队检查它是否做对。

DeepSeek和Qwen在Live模式负责理解与选工具，LangChain负责模型—工具之间的往返，Python后端执行实际模拟业务。工具数据不是模型凭空生成的。RAG将本地政策检索给模型；Chroma保存真实Embedding向量，但政策本身仍是虚构的比赛语料。

## 第一次运行

先按 [安装与Key手册](01_安装启动与API配置.md) 安装依赖。无需理解代码即可双击 `启动_离线模式.cmd`。在线模式须配置自己的Key，点击发送才调用真实模型。不要把A的历史请求成功当作你当前电脑已连通。

建议先录无需网络的内容，再决定是否进行付费Live演示。启动终端必须保留，Ctrl+C停止服务。根目录 `交付版本.json` 可截图展示版本；正式成绩取B的本轮报告，不取A自测数量当比赛成绩。

## 功能验收与画面

| 顺序 | 操作/输入 | 预期与应检查内容 | 适合截图 |
|---|---|---|---|
| 1 | 离线模式查“明天上海到杭州的高铁二等座” | 显示虚构车次；执行摘要有query_tickets；卡片和工具结果一致 | 对话+车次卡片+模式徽标 |
| 2 | 在同会话换路线或交通方式 | 参数跟随明确切换，不错误继承席别；缺条件应澄清 | 两轮对话和参数 |
| 3 | 离线按实际车次尝试锁座/下单，按提示填虚构资料 | 先lock再create；支付仅模拟状态；不要输入真人资料 | 真实工具顺序、订单模拟标记 |
| 4 | 问“锁座后多久必须完成支付？” | search_policy返回政策来源；检查P11与原始证据，而非只看回答流畅 | 政策卡片、doc_id |
| 5 | 工作台查看本轮Trace与JSON | 参数、工具成功标记、耗时、finish_reason可检查 | 工具表、审计旁证 |
| 6 | 新隔离实验启用一项变异，正常/变异分开 | 展示故意缺陷与审计证据；恢复正常后新建会话 | 变异开关、真实差异 |
| 7 | RAG页面切Keyword/Vector/Hybrid、查看历史48题 | 缓存和历史指标明确标记；不把回放当新Live | 指标对照、无答案案例 |
| 8 | 在线切Qwen或DeepSeek并新建会话 | 右上徽标/费用文字一致；查票与政策咨询只读；其余六工具禁止 | Provider、工具调用和回复 |
| 9 | 有已保存Live记录后预览LangSmith并确认导出 | POST202不是最终成功；只有GET内容匹配才remote_verified=true | 脱敏预览和真实回执 |

界面的旋转/处理状态只表示正在执行，不是模型内部思维链。离线HTTP桩、Mock变异和历史回放都必须标注，不得剪辑为实时真实API成功。Live错误也应保留，不能用旧成功结果替换。

## 5—10分钟视频建议

1. 0:00—0:45：团队分工与问题背景，A开发/B正式测试/C验收展示。
2. 0:45—2:00：启动、离线查票、多轮切换；说明模拟数据。
3. 2:00—3:15：Mock购票工具顺序与幂等保护；说明Live只读边界。
4. 3:15—4:30：政策检索、doc_id、RAG三模式和无答案处理。
5. 4:30—6:00：工具表、JSON、独立Trace审计与变异正常/异常对照。
6. 6:00—7:30：可选的自费真实模型只读演示；或明确标注的历史真实证据回放。
7. 7:30—8:30：LangSmith手动脱敏导出与GET核验；没有新远端验证就展示“未验证”。
8. 8:30—9:30：B实际质量结论、当前限制与下一步；不要编造覆盖率或通过率。
