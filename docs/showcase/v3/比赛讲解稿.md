# Ticket Agent V3：作品讲解参考稿

约2—3分钟，可根据B最终测试结果补充正式成绩。当前讲解必须说明Mock运行与真实模型待验证。

大家好，我们的项目是Ticket Agent，一个面向智能体测试的模拟出行助手。它支持高铁与机票查询、模拟订票与退票，以及带来源的票务政策检索。所有数据和支付均为虚构模拟。

项目的重点是让Agent行为可检查。用户提出需求后，系统通过工具查询业务数据；订票必须先查询、锁座，再创建订单；政策咨询调用知识库检索，而不是直接触发支付。每一步会记录工具名称、实际参数、执行结果、耗时和终止原因。

V3引入了真正的LangChain框架。框架负责模型调用循环、工具执行和结果回传；模拟模型只产生可控的工具请求。原来的Python执行模式继续保留，原八工具和团队接口没有被重写。

这里首先展示查明天上海到杭州的高铁。右侧可以看到query_tickets，以及具体日期、席别和工具结果。这些是Mock数据库结果，不是真实售票库存。

接着输入订票请求，工具顺序是query_tickets、lock_seat、create_order，返回待支付订单。系统不会因为用户说订票就自动支付。支付、退票还要经过独立业务授权和后端状态检查。

再询问“锁座后多久必须完成支付”，系统调用search_policy，并返回P11政策来源。本轮不执行支付操作。这展示了操作与规则咨询的区别。

页面中的执行轨迹是实际工具记录，不是模型内部思维链。处理中图标只表示请求等待。我们另外提供了界面设计稿，用历史Mock数据展示更清晰的票卡、步骤和政策来源；设计稿和原应用真实截图已分别标注。
