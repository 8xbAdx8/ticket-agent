# V3 六工具迁移评估与实际结果

日期：2026-10-13；两个查询工具原型提交 `92efc2a739bd3712d2ff62910bf8944cd9ad81b9` 通过后实施。

全部复用 `target/tools.py` 和 `target/mock_core.py`，没有重写数据库。参数 Schema 和团队 contract 不变。

| 工具 | 原约束与风险 | V3 实施 | 实际验证 |
|---|---|---|---|
| monitor_seat | 只能售罄班次候补；只返回模拟 ID，不是后台轮询服务 | 保留后端约束，要求订票/候补授权 | 无票候补成功、有票候补失败 |
| lock_seat | 会扣库存，原函数不幂等，模型重复调用风险 | 本轮明确授权；一轮至多一次成功锁座，后续拒绝并记录失败调用 | 跨模型轮和同一模型轮重复调用均只扣一次库存 |
| create_order | 有效 lock_id、乘客一致、本人联系号码；同锁幂等 | 还要求本轮实际成功的 lock_id；底层校验继续保留 | 查询→锁座→下单成功；借用本轮之外锁被拒绝 |
| pay_order | 本人订单，pending→paid；重复支付 duplicate_pay | 要求当前明确支付请求；订单号来自明确输入或最近真实工具结果 | 咨询/否定/订票请求不能支付；重复支付提示与状态正确 |
| cancel_order | 仅 pending/paid；释放库存一次，模拟手续费 | 要求当前明确取消/退票请求及订单引用 | 正常退票恢复库存；再次退票失败、不多释放 |
| query_order | 只查询固定模拟身份；没有真实账户登录 | 原查询权限不变 | 强制模型查询其他手机号被拒绝 |

`AGENT_LC_TOOLSET=read_only` 默认只注册原型两个工具；`all` 注册八工具。六种故意变异只在 legacy 开放，LangChain 初始化发现变异会明确拒绝。

授权层位于 `target/write_authorization.py` 和框架 `wrap_tool_call`，不依赖模型是否遵守 Prompt。被拒绝的工具请求仍属于真实调用尝试，记入 Trace（ok=false），但没有执行票务后端。对成功锁座没有隐式自动重试，对支付/创建订单继续使用后端原幂等行为。

限制：授权采用保守的中文命令规则，不是通用语言理解或生产权限系统；含问号、政策问句、否定、引用/假设等可能要求用户重述。一次请求多份不同路线订单、跨轮直接消费旧锁不支持。用户指定订单仍需底层本人权限验证。库存/订单属于同一个配置模拟身份，与会话记忆隔离是两件事；正式测试用例需独立 DB。

A 证据：`docs/evidence/v3/orders_unit_passed.txt`（最初12项）；`final_legacy_smoke/unit.txt`（最终13项订单自测及13项原型自测）；`final_framework/api_results.json` 和 `framework_events.json`（11轮 API、覆盖8工具）。原始失败 `orders_unit_utf8.txt` 保留：A 的断言措辞不匹配和测试 SQLite 连接未 close，已修正测试代码，不涉及 B 正式判定。
