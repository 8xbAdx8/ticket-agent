# Ticket Agent · 评委图形启动版

Ticket Agent 是一个铁路出行模拟与智能体测试工作台。评委可以在用户端体验查询和模拟购票，再到测试工作台检查智能体是否选对工具、遵守确认流程，以及判定能否追溯到实际执行证据。

## 打开项目

1. 在 **Windows 10/11 x64** 上把整个 ZIP 解压到本地可写的文件夹，建议预留 **2 GB**。进入同时包含 `Ticket Agent.vbs`、`Ticket Agent.pyw` 和本 README 的目录。
2. 双击 **`Ticket Agent.vbs`**。首次会展开内置 Python、依赖和完整铁路静态库，并显示准备窗口。解包完成后，Ticket Agent 图形启动器会打开。
3. 选择 **Mock（本地）**，点击 **启动**。页面默认打开客户端，也可从启动器点击「打开客户端」或「打开测试控制台」。
4. 完成体验后，在启动器点击「停止服务」。关闭浏览器页面后，可以从启动器再次打开页面。

如果这台电脑已将 `.pyw` 文件关联到 Python，也可以双击 **`Ticket Agent.pyw`** 进入同一启动器。使用 `.vbs` 入口需要 Windows Script Host 可用。Mock 演示使用包内环境，无需预装 Python、联网或填写 API Key。

## 推荐评审路线

### 用户端 · 从查询到模拟交易

在客户端输入：

> 查询 2026-11-18 上海虹桥到杭州东的铁路车次，出发站编码 AOH，到达站编码 HGH。

展开车次的经停信息，或点击「选择此车次」填写模拟乘车人、选择席别，再按页面提示提交。订单区可以查看模拟订单和支付状态。若要演示退票或改签，请先按页面提示完成相应的模拟确认。演示请填写合成信息。

车站、车次和经停来自包内铁路静态库。库存、报价、订单和支付在本地模拟，页面结果仅用于演示和测试。

### 测试端 · 运行用例并核对证据

打开「测试控制台 → AI 场景总测试」，选择 **Mock**，点击「开始本轮测试」。当前交付版在这里使用独立场景，进入测试页后即可启动，无需预先完成购票对话。

| 页面 | 适合查看的内容 |
| --- | --- |
| AI 场景总测试 | 本轮场景、执行状态和判定明细 |
| 质量分析 | 客观断言、通过、失败及无法判定 |
| RAG / 多轮 / 安全 | 检索、上下文继承和操作权限相关证据 |
| 边界与异常测试 | 边界用例、M1–M8 异常注入和检测依据 |
| 性能测试 | 本轮采样的耗时、调用次数或并发证据 |

核对某条用例时，建议同时看**测试目标、真实工具调用和断言明细**。某一维度未触发或证据不足时，按页面状态解读。Mock 的执行与断言使用本地环境，真实模型的语义评判需要另行使用 Live。

### 开发者端 · 核对实现

从侧栏进入「开发者工作空间」，可以查看 Agent 思考分析、提示词、工具、知识库、记忆、工作流与风控的说明。可展开页面附带的源码片段，核对介绍与实现。

## 启动问题与离线预览

| 现象 | 处理方式 |
| --- | --- |
| 首次启动处于准备中 | 保持窗口开启，等待本地解包完成。确认有足够的可用磁盘空间。 |
| 找不到启动文件或提示缺少组件 | 确认已将整个 ZIP 解压到本地，并在解压目录中打开入口。 |
| 浏览器没有自动打开 | 在启动器点击「打开客户端」或「打开测试控制台」，也可复制窗口里显示的本地地址。 |
| 启动失败 | 查看根目录的 `启动日志.txt`。启动器已经打开时，也可以点击「查看日志」查看服务日志。 |
| 当前电脑无法启动本地应用 | 用浏览器打开 [评审预览.html](评审预览.html)，查看静态产品和测试说明。 |

启动器还提供 Live 选项，供已配置模型服务凭据的环境使用。Live 需要联网，并可能产生模型费用。现场离线演示可使用 Mock。

## 目录说明

- `ticket-agent/` 包含项目源码、测试资料与本地运行数据。
- `bootstrap/` 和 `payload/` 用于首次启动，随项目目录一起保留。
- `交付校验.json` 记录内置运行环境和铁路库的校验信息，`交付清单.txt` 提供快捷入口提示。
